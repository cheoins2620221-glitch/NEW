# ScreenTime Guardian (Android, Kotlin) — v0.4

자녀(또는 본인) 스마트폰의 전체 사용시간을 관리하는 자기관리형 앱. 부모가 원격으로 앱마다 개별 설정을 하는 방식이 아니라, **설치한 사람이 직접 총 사용 한도와 허용 앱을 정하고, 한도를 넘으면 자동으로 잠기는 방식**입니다.

## v0.4에서 바뀐 것 (구조 전면 개편)

이전 버전(v0.3)까지는 "앱마다 개별 한도"를 부모가 설정하는 구조였습니다. 이번에 다음과 같이 바뀌었습니다.

- **앱별 개별 한도 → 총 사용 한도 하나로 통합**: 허용 앱을 제외한 모든 앱의 사용시간을 합산해서 하루 한도(기본 5시간)와 비교합니다.
- **허용 앱 목록 추가**: 전화 앱과 문자(SMS) 앱은 서비스가 시작될 때 **자동으로 감지되어 항상 허용**됩니다. 그 외에 계속 쓰고 싶은 앱은 "4. 허용 앱 추가"에서 직접 추가할 수 있습니다.
- **한도 초과 시 동작**: 총 사용시간이 한도를 넘으면, 허용 앱을 제외한 **모든 앱**이 열릴 때마다 자동으로 차단됩니다 (특정 앱 하나만 막는 게 아님).
- **그레이스 피리어드도 하루 1회로 변경**: 처음 한도를 넘겼을 때 한 번 카운트다운을 주고, 그 이후로는 어떤 비허용 앱을 열든 바로 차단됩니다.

시간 은행(저축/인출), 대출(미리쓰기제/기한제), 리워드 환전, PIN 보호 기능은 이전과 동일하게 유지되며, 기준만 "앱별 한도"에서 "총 사용 한도"로 바뀌었습니다.

## 핵심 동작 흐름

1. 앱 실행 → 접근성/오버레이 권한 켜기
2. 서비스가 시작되면 전화/문자 앱이 자동으로 허용 목록에 등록됨
3. "3. 총 사용 한도 설정"에서 하루 한도(분)와 그레이스 시간(초) 설정
4. 허용 앱 외의 모든 앱을 쓴 시간이 합산되어 한도와 비교됨
5. 한도 초과 → 오늘 처음이면 그레이스 카운트다운 후 홈 이동 + 차단 오버레이, 이후로는 즉시 차단
6. 저축해둔 시간이나 대출로 한도를 늘릴 수 있음 (기존 로직 그대로)

## 파일 구조

```
app/src/main/java/com/parentcontrol/screentime/
  data/
    AllowedAppEntity.kt   # 허용 앱 목록 (신규)
    AppUsageEntity.kt     # 날짜별 앱 사용시간 (허용 앱은 기록 안 됨)
    TimeBankEntity.kt     # 총 사용한도 + 저축/대출/리워드/PIN (v0.4 확장)
    AppDao.kt, AppDatabase.kt (v3)
  manager/
    TimeBankManager.kt    # 총 사용한도 기준 정산 + 저축/대출/리워드/PIN
  service/
    AppMonitorAccessibilityService.kt  # 전화/문자 자동 허용 + 총 사용한도 기준 차단
    BlockOverlayService.kt
  ui/
    MainActivity.kt, AllowedAppAdapter.kt (신규)
res/layout/activity_main.xml (총 사용한도 + 허용앱 목록 UI)
```

## 테스트 순서

1. 앱 설치 → 접근성/오버레이 권한 켜기
2. "3. 총 사용 한도 설정"에서 총 한도를 짧게(예: 2분)로 설정해서 빠르게 테스트
3. 아무 일반 앱(예: 유튜브)을 열어 2분 넘게 사용 → 그레이스 카운트다운 → 홈 이동 + 차단 확인
4. 전화 앱이나 문자 앱은 아무리 써도 안 잠기는지 확인
5. "4. 허용 앱 추가"에서 다른 앱(예: 계산기)을 허용 목록에 추가한 뒤, 한도를 넘긴 상태에서도 그 앱은 잠기지 않는지 확인
6. 저축/대출/리워드는 v0.3과 동일하게 테스트 (README v0.3 내용 참고)

## 알려진 한계

- 전화/문자 기본 앱 자동 감지는 기기·제조사에 따라 실패할 수 있음 (그 경우 수동으로 허용 목록에 추가해야 함)
- 부모-자녀 기기 간 원격 동기화 없음 (기기 로컬에서 직접 설정)
- 자정 정산은 앱이 켜져 있을 때만 체크됨 — `WorkManager` 예약 필요
- 리워드 포인트의 실제 혜택(기프티콘 등) 연동은 없음 (포인트 잔액 관리까지만)
- PIN은 평문 저장 — 실제 배포 시 해시 필요
- DB 스키마가 v1→v3까지 여러 번 바뀌어서 기존에 설치했던 앱이 있다면 데이터가 초기화됩니다
